# Бизнес-приложение. Ответы API и обновление сессии

Поток DV, пункт 32, 26.11.2026. Случаи воспроизведены через публичные методы `BusinessApi` с подменой транспорта. Для сессии тесты управляют порядком ответов сервера и проверяют число запросов и значение в хранилище.

## Исправлено в этом PR

| Модуль                       | Случай                                                                                                 | Ожидание                                                                               | Факт до исправления                                                                                                                                  | Серьёзность |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| `api.ts` · обновление сессии | Два запроса получают 401 с прежними данными входа. Второй ответ может прийти уже после первого повтора | Одно обновление на оба запроса, у каждого не больше одного повтора                     | Оба запроса обновляли сессию. При одновременном использовании одноразового токена отказ второго обновления мог стереть только что сохранённую сессию | Высокая     |
| `api.ts` · смена аккаунта    | После смены аккаунта приходят 401 старого запроса или ответ уже начатого обновления                    | Старый запрос завершается без повтора, новая сессия сохраняется                        | Старый запрос мог начать обновление от имени нового пользователя. Запоздалый ответ обновления мог перезаписать или удалить новые данные входа        | Высокая     |
| `api.ts` · отмена            | Экран закрыт, пока его запрос ждёт общего обновления сессии                                            | Чтение сразу завершается с причиной отмены. Остальные запросы дожидаются обновления    | Отменённое чтение продолжало ждать и после обновления могло снова вызвать транспорт                                                                  | Средняя     |
| `api.ts` · ответ обновления  | HTTP 200 с `{}`, пустой строкой или числом в поле токена                                               | Отклонить ответ и сохранить прежние данные входа для следующей попытки                 | `restore()` мог вернуть `true` без пригодного токена доступа или передать повреждённый токен обновления в хранилище                                  | Высокая     |
| `api.ts` · чтение JSON       | HTTP 200 с пустым телом, HTML или обрезанным JSON                                                      | Сообщить об ошибке ответа сервера                                                      | Исключение разбора JSON попадало в обработчик отсутствия сети, хотя сервер ответил                                                                   | Средняя     |
| `api.ts` · ответ со списком  | `locations()` получает HTTP 200 с `null` или HTTP 204                                                  | Отклонить ответ до передачи списка на экран. Пустой список салонов передаётся как `[]` | Метод возвращал `null` или `undefined`, а при выборе салона приложение пыталось перебрать это значение                                               | Средняя     |

## Открытые находки

| Модуль                     | Случай                                                                             | Ожидание                                                                                 | Факт                                                                                                                                                                                                                                                                                      | Серьёзность |
| -------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| `api.ts` · `publicHours()` | HTTP 200 с `{"timezone":"Europe/Warsaw"}` без расписания                           | Отклонить неполное расписание до расчёта статуса салона                                  | `openingHours` и `todayHours` получают `undefined`. При обращении к `todayHours.date` расчёт завершается с `TypeError`. Два существующих теста языка используют ответ `{}` как успешный. Для исправления нужно также обновить их данные, а пакет 32 разрешает только новые тестовые файлы | Средняя     |
| `api.ts` · ожидание ответа | При запуске `restore()` запрос уходит, но транспорт не возвращает ответ или ошибку | После предельного времени снова дать пользователю возможность войти или повторить запрос | У `BusinessApi` нет общего таймера. При запуске приложение продолжает ждать. Часть экранов отдельно ограничивает ожидание 30 секундами. Общий предел затронет и медленные корректные запросы, поэтому его выбор выходит за рамки этого пакета                                             | Средняя     |

Тесты в `edge-api-responses.test.ts` проверяют HTTP 400, 401, 403, 404, 409, 429, 500 и 503, тела ответов, ошибки чтения и кодирование польских букв и разделителей в адресе. В `edge-api-session.test.ts` проверяются повтор запроса, смена аккаунта, ротация токена, таймаут транспорта и отмена по сигналу вызывающей стороны.
