## Вход и доступ (задача 2)

| Что                  | Как сделано                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Пароли               | Argon2id, минимум 10 символов                                                                                      |
| Токен доступа        | JWT HS256, 15 минут, в заголовке `Authorization: Bearer`                                                           |
| Refresh-токен        | 30 дней, меняется при каждом обновлении; повтор старого отзывает всю сессию                                        |
| Где хранится refresh | Веб: httpOnly-cookie `bp_refresh` (SameSite=Strict, путь `/v1/auth`); мобильные: в теле ответа → Keychain/Keystore |
| Сессии               | По устройствам: `GET /v1/me/sessions`, выход с устройства — `DELETE`                                               |
| Email                | Подтверждение обязательно до входа; ссылки одноразовые, хранится только хеш                                        |
| Сброс пароля         | Ссылка на 1 час; после сброса все устройства выходят                                                               |
| Ограничение частоты  | Вход: 10 попыток на email за 15 минут; письма: 5 в час на адрес                                                    |
| Изоляция салонов     | Всё под `/v1/organizations/:orgId` проверяет членство; чужое → 404, роль не позволяет → 403                        |
| Роли                 | Владелец — всё; менеджер — только свои филиалы, без создания филиалов; мастер — просмотр                           |

Ограничение частоты хранится в памяти процесса: при нескольких экземплярах API перенесём в PostgreSQL.
Письма подтверждения и сброса отправляются сразу; письма о записях идут через очередь (задача 4).

## Услуги, мастера и свободное время (задача 3)

| Что                  | Как сделано                                                                                                             |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Цена                 | Целое число в грошах (`priceGrosze`), без дробей                                                                        |
| Длительность и буфер | Шаг 5 минут; буфер занимает мастера, но не показывается клиенту                                                         |
| Услуги не удаляются  | Выключаются (`active: false`) — на них будут ссылаться записи                                                           |
| Рабочие часы         | Недельный шаблон в местном времени филиала; перерыв = два интервала в день; `24:00` — конец дня                         |
| Особые дни           | Часы на конкретную дату заменяют шаблон в этот день                                                                     |
| Отпуск и блокировки  | Период в местном времени, хранится в UTC; убирает слоты                                                                 |
| Слоты                | Услуга + буфер целиком внутри рабочих часов и вне занятого времени; шаг — из настроек филиала                           |
| Переход времени      | 29.03 часа 02:00–03:00 нет — слотов в нём нет; 25.10 час 02:00 повторяется — слот предлагается один раз                 |
| «Любой мастер»       | Каждый слот содержит список свободных мастеров (`staffIds`)                                                             |
| Для сотрудников      | `GET …/availability` — без минимального срока и горизонта, только не в прошлом                                          |
| Для клиентов         | `GET /v1/public/locations/{slug}/availability` — минимальный срок и горизонт салона; только если включена онлайн-запись |
| Горизонт             | При горизонте 30 дней последний доступный день — сегодня + 30                                                           |
| Защита в базе        | CHECK-ограничения: интервалы, день недели, цена, период отпуска                                                         |

Отложено: категории услуг, переводы названий услуг, приглашение сотрудников в аккаунт (появятся вместе с веб-кабинетом).

## Запись клиента (задача 4)

| Что                         | Как сделано                                                                                                                         |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Шаги онлайн-записи          | 1) удержание слота на 10 минут → 2) имя, телефон, email, согласие → код на email → 3) код → запись подтверждена                     |
| Двойное бронирование        | Запрещено самой базой: `appointment_no_overlap` (EXCLUDE по мастеру и времени с буфером); удержанные и подтверждённые записи        |
| Одновременные запросы       | Запись на одного мастера идёт по очереди (`pg_advisory_xact_lock`), иначе PostgreSQL мог бы прервать их как взаимную блокировку     |
| Истёкшие удержания          | Освобождаются в той же транзакции, что и новая запись — даже если фоновая задача не работает; подтверждение сверяется с часами базы |
| Код                         | 6 цифр, хранится только хеш; живёт не дольше удержания; максимум 3 отправки и 5 попыток                                             |
| Ограничения                 | 5 удержаний на IP за 10 минут, 10 кодов на email в час                                                                              |
| Управление записью клиентом | Ссылка из письма `/{язык}/m/{токен}`: перенос и отмена до срока салона (по умолчанию за 2 часа)                                     |
| Запись салоном              | Телефон, «с улицы»; вне рабочих часов — только с `allowOutsideHours=true`; поверх другой записи — никогда                           |
| Мастер (роль staff)         | Видит и меняет только свои записи                                                                                                   |
| Изменения                   | Номер версии: устаревшая версия → 409 `VERSION_CONFLICT`; история событий у каждой записи                                           |
| Повтор запроса с телефона   | Заголовок `Idempotency-Key`: повтор возвращает тот же ответ; тот же ключ с другим телом → 422                                       |
| Письма                      | Очередь в таблице `notification_outbox`: письмо сохраняется в той же транзакции, что и изменение; 5 попыток с паузами               |
| Дубли писем                 | У каждого письма постоянный ключ; повтор после сбоя не создаёт второе письмо                                                        |
| Напоминание                 | За 24 часа; пропускается, если запись перенесли или отменили                                                                        |
| Персональные данные         | Контакты из неподтверждённого удержания стираются через 24 часа                                                                     |

**Очередь писем — своя, вместо pg-boss (решение 23.10.2026, вариант А).** Укреплена:

- письма берутся по одному, блокировка 5 минут, одна отправка не дольше 1 минуты;
- неотправленные (после 5 попыток) видны администратору платформы: `GET /v1/admin/outbox`, `/failed`,
  повторная отправка `POST /v1/admin/outbox/retry`; страница в кабинете — «Kolejka e-maili»;
- оповещение администраторам (`PLATFORM_ADMIN_EMAILS`) не чаще раза в час, если есть неотправленные или письмо
  ждёт дольше `OUTBOX_ALERT_AFTER_MINUTES` (15);
- очистка: отправленные удаляются через 30 дней, неотправленные — через 90;
- адреса из текстов ошибок провайдера не сохраняются;
- провайдер Resend (`MAIL_TRANSPORT=resend`) получает ключ против дублей (`Idempotency-Key`, 24 часа).
  Проверено на имитации Resend по его документации; на настоящем аккаунте — после его создания.
  Данные аккаунта Resend хранятся в США — решение о провайдере за владельцем (GDPR).

## API для календаря и права мастеров (этап 1)

| Что                      | Как сделано                                                                                                                             |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| Права мастеров           | Категории мастеров с набором прав + личные исключения; итог = исключение → категория → значение по умолчанию                            |
| Проверка прав            | На сервере: чего мастеру нельзя видеть (телефон, email, история, заметки, цена), того нет в ответе API                                  |
| Права по умолчанию       | Можно: создавать, переносить и отменять свои записи. Нельзя: контакты, история, заметки, чужие записи, вне часов, свои деньги           |
| Блокировки времени       | На мастера или на весь филиал, с причиной; не пересекаются с записями (проверка под той же блокировкой, что и запись)                   |
| Календарь одним запросом | `GET …/calendar`: часы мастеров, отсутствия, записи, блокировки. Обновление раз в 30 с с `If-None-Match` → 304, если ничего не менялось |
| Категории и цвет услуг   | Категории с порядком; цвет и порядок у услуги                                                                                           |
| Карточка клиента         | Добавление и правка, заметка салона, метки; история визитов; метки «первый визит» и «мастер выбран клиентом» у записи                   |
| Приглашения              | По email, ссылка на 7 дней, только для того же подтверждённого email; повторное приглашение отменяет старую ссылку                      |
| Удаление из команды      | Доступ пропадает сразу; профиль мастера и записи остаются в календаре                                                                   |
| Лента уведомлений        | `GET /v1/me/notifications`: новая, перенесённая, отменённая запись; пишется в той же транзакции; без контактов клиента                  |

Блокировки и записи хранятся в разных таблицах, поэтому запрет их пересечения проверяется кодом под блокировкой мастера и филиала,
а не правилом базы (как у записей между собой).

## Веб-кабинет и онлайн-запись (этапы 2 и 3)

| Что                 | Как сделано                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Технология          | Next.js (`apps/web`), все страницы — клиентские; браузер обращается к API через тот же адрес (`/v1/*` проксируется) |
| Вход                | Токен доступа только в памяти; refresh — httpOnly-cookie API; после перезагрузки страницы сессия восстанавливается  |
| Языки               | `/pl`, `/uk`, `/ru`, `/en` — переключатель на каждой странице; тексты в `apps/web/lib/i18n`                         |
| Стиль               | GESTALT: чёрное на белом, Michroma для заголовков и времени, скругления 4–6 px; цвет — у услуг и линии «сейчас»     |
| Календарь           | День по мастерам, неделя-полоса, обновление раз в 30 с (ETag → 304), прокрутка к текущему времени                   |
| Права мастера       | Экран показывает только то, что вернул сервер; запрещённые данные (телефон и т. п.) сервер не отдаёт                |
| Онлайн-запись       | `/{язык}/b/{slug}`: услуга → мастер или «любой» → день и время → данные → код → готово (+ файл .ics)                |
| Управление записью  | `/{язык}/m/{токен}` из письма: перенос и отмена до срока салона                                                     |
| Проверка в браузере | CI-задача `e2e`: API + веб + PostgreSQL + Mailpit + Playwright; снимки экранов — в ветке `e2e-screenshots`          |

Отклонения и ограничения:

- В спецификации — типизированный клиент `packages/api-client`, сгенерированный из OpenAPI. Сейчас типы ответов API
  написаны вручную (`apps/web/lib/types.ts`); генерация — отдельной задачей.
- В шрифте Michroma нет кириллицы: на украинском и русском заголовки показываются основным шрифтом.
- API за прокси веб-сервера должен знать адрес посетителя: `TRUST_PROXY=1` (иначе лимиты частоты считаются на всех вместе).

## Приложение на телефон и компьютер (этап 4, начало)

Кабинет салона ставится как приложение (PWA) — без App Store и Google Play:

| Где                        | Как установить                                                          |
| -------------------------- | ----------------------------------------------------------------------- |
| Android, Chrome, Edge      | кнопка «Zainstaluj aplikację» в меню «Więcej» или внизу боковой панели  |
| iPhone, iPad               | Safari → «Udostępnij» → «Do ekranu początkowego» (шаги показаны там же) |
| Mac, Windows (Chrome/Edge) | та же кнопка или значок установки в адресной строке                     |

- Манифест — на языке интерфейса (`public/manifests/salon-{pl,uk,ru,en}.webmanifest`), у всех один `id`,
  поэтому это одно приложение; запуск — `/{язык}/app`.
- Service worker (`public/sw.js`) не хранит данные салона на устройстве: страницы и `/v1/*` всегда из сети,
  в кеше только страница «нет соединения».

**Push-уведомления (Web Push).** Новые, перенесённые и отменённые записи приходят на телефон и компьютер,
даже когда приложение закрыто. Включаются в «Więcej» и «Powiadomienia» → «Włącz powiadomienia» на каждом устройстве.

| Что           | Как сделано                                                                                                          |
| ------------- | -------------------------------------------------------------------------------------------------------------------- |
| Источник      | Лента уведомлений: строка пишется в транзакции изменения записи, фоновая задача отправляет ещё не отправленные       |
| Надёжность    | `FOR UPDATE SKIP LOCKED`, до 3 попыток; старше 1 часа не отправляются (в ленте остаются)                             |
| Устройства    | `POST /v1/me/push-subscriptions`, выключить — `…/remove`; отписавшееся устройство (404/410) удаляется сразу          |
| Текст         | На языке пользователя: время, клиент, услуга, мастер — без телефона и email (видно на экране блокировки)             |
| Ключи         | `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` (новая пара: `node apps/api/scripts/vapid-keys.mjs`); без них push выключен |
| iPhone и iPad | Только в установленном приложении (iOS 16.4+); в Safari без установки — подсказка «сначала установите»               |
| Тесты         | `PUSH_TRANSPORT=memory`: отправка, повтор, удаление отписавшегося устройства, отказ после 3 попыток                  |

- Иконки — из логотипа GESTALT (`public/icons`).

## Приложение клиента «Мои визиты» (этап 4, задача 1)

Клиент входит без пароля и видит свои записи во всех салонах платформы. Вход клиента отделён от аккаунтов салонов.

| Что                | Как сделано                                                                                                     |
| ------------------ | --------------------------------------------------------------------------------------------------------------- |
| Вход               | `POST /v1/client/auth/code` (email) → письмо с 6-значным кодом → `POST /v1/client/auth/verify`                  |
| Код                | 10 минут, хранится только хеш, одноразовый; 5 неверных попыток → новый код; 5 кодов в час на адрес              |
| Без «прощупывания» | Ответ одинаковый, есть у адреса визиты или нет                                                                  |
| Сессия             | 90 дней. Веб: httpOnly-cookie `bp_client` (путь `/v1/client`); мобильные: токен в теле → `Bearer`; хранится хеш |
| Person             | Клиент платформы по подтверждённому email (задел из спецификации); язык писем — `PATCH /v1/client/me`           |
| Какие визиты видны | Записи карточек клиентов салонов с тем же email: подтверждённые, отменённые, завершённые, неявки; не удержания  |
| Списки             | `GET /v1/client/appointments?scope=upcoming` (ближайшие первыми) и `scope=past` (последние 50)                  |
| Отмена и перенос   | `POST …/appointments/{id}/cancel` и `/reschedule` — те же правила и письма, что и по ссылке из письма           |
| Чужая запись       | Выглядит как несуществующая (404)                                                                               |
| «Записаться снова» | В ответе `bookAgain`: салон, услуга, мастер; `null`, если салон больше не принимает эту услугу онлайн           |
| Что не отдаётся    | Заметки и метки салона, контакты — только то, что клиент видит по ссылке из письма                              |
| Очистка            | Неиспользованные коды удаляются через сутки после истечения, истёкшие сессии — сразу                            |

Записи, которые салон внёс с email клиента вручную, тоже видны владельцу этого email (как в Booksy по телефону).

**Экраны** (`/{язык}/c`):

| Экран                  | Что там                                                                                                |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| Вход                   | E-mail → код из письма; «Wyślij kod ponownie», «Inny e-mail»; после перезагрузки сессия сохраняется    |
| Список                 | Вкладки «Nadchodzące» и «Historia»: время, услуга, мастер, цена, салон; в истории — «Umów ponownie»    |
| Визит `/{язык}/c/{id}` | Тот же экран, что и по ссылке из письма (общий компонент): перенос, отмена, файл .ics, «Umów ponownie» |
| «Umów ponownie»        | Страница записи салона с `?service=…&staff=…` открывается сразу на выборе времени                      |
| После записи           | На экране «Do zobaczenia!» — ссылка «Wszystkie moje wizyty»                                            |

Проверка в браузере: шаг в основном e2e-сценарии (вход по коду из Mailpit, список, визит, «Umów ponownie»).
**Установка на телефон.** «Мои визиты» — отдельное приложение, не кабинет салона: свой манифест
(`public/manifests/visits-{pl,uk,ru,en}.webmanifest`, `id: /c`, запуск — `/{язык}/c`), название
«GESTALT · Wizyty» (UA «Візити», RU «Визиты», EN «Visits»), тот же service worker. Кнопка «Zainstaluj aplikację»
и шаги для iPhone — под списком визитов.

## Формат ошибок API

```json
{ "error": { "code": "NOT_FOUND", "message": "...", "requestId": "..." } }
```

`code` — машинный код; веб и мобильные приложения переводят его на язык пользователя.
Коды: `VALIDATION_ERROR` (+ `details`), `UNAUTHORIZED`, `INVALID_CREDENTIALS`, `EMAIL_NOT_VERIFIED`,
`INVALID_TOKEN`, `INVALID_REFRESH_TOKEN`, `FORBIDDEN`, `NOT_FOUND`, `SLUG_TAKEN`, `VERSION_CONFLICT`,
`RATE_LIMITED`, `STAFF_SERVICE_MISMATCH`, `SLOT_TAKEN`, `OUTSIDE_WORKING_HOURS`, `IN_THE_PAST`, `NOT_STARTED`,
`HOLD_EXPIRED`, `CODE_NOT_SENT`, `CODE_EXPIRED`, `INVALID_CODE`, `TOO_MANY_ATTEMPTS`, `TOO_MANY_CODES`, `TOO_LATE_TO_CHANGE`,
`IDEMPOTENCY_KEY_REUSED`, `REQUEST_IN_PROGRESS`, `CATEGORY_NAME_TAKEN`, `INVITATION_EXPIRED`, `EMAIL_MISMATCH`,
`ALREADY_MEMBER`, `STAFF_ALREADY_LINKED`, `CANNOT_REMOVE_OWNER`, `INTERNAL_ERROR`.
