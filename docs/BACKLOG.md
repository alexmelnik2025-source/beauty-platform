# Очередь задач агента-разработчика

Агент «Разработка приложения» (задача по расписанию) берёт **первую незакрытую** задачу сверху,
делает её на отдельной ветке, проверяет в CI и переносит в `main`. Владелец может переставлять,
добавлять и вычёркивать задачи — порядок здесь главный. Цель: к марту 2027 запись и приложения готовы,
апрель — тест, открытие нового барбершопа ≈ конец апреля 2027 (план: https://claude.ai/artifact/QbqGrxf1uWw4u9nFmM3c9a).

Правила для каждой задачи: тесты на настоящей PostgreSQL, 4 языка (PL/UA/RU/EN), права и изоляция салонов
проверяются на сервере, никаких платных сервисов, секретов в репозитории и выкладки на серверы.

## Очередь

- [ ] **1. Приложение клиента «Мои визиты».** Вход клиента без пароля: email → 6-значный код. Список всех его
      записей во всех салонах (по подтверждённому email), детали, перенос и отмена по правилам салона,
      «записаться снова» (та же услуга и мастер). Отдельный раздел `/{язык}/c`, свой манифест PWA
      («GESTALT · Wizyty»), установка на телефон. Сущность Person (спецификация, «задел на будущее»).
- [ ] **2. Страница записи помнит клиента.** После успешной записи имя, телефон и email сохраняются на
      устройстве (с согласия, галочка «запомнить меня»); в следующий раз поля заполнены. После записи —
      кнопка «Установить приложение» → раздел клиента, запись уже там.
- [ ] **3. Языки общения.** У филиала и у мастера — список языков (pl, uk, ru, be, en). Настройка в кабинете
      («Ustawienia», карточка мастера), показ значками на странице записи. Основа для фильтра на карте.
- [ ] **4. Код по SMS (без провайдера).** Абстракция отправки SMS (как письма): транспорт `memory` для тестов и
      `log` для разработки. Клиент выбирает, куда прислать код: SMS или email. Подключение реального
      польского SMS-шлюза — только после решения владельца (платно), здесь не делать.
- [ ] **5. Кнопка записи для сайта и Instagram.** Код вставки кнопки/окна записи для любого сайта (как виджет
      Booksy, но наш), короткая ссылка для био Instagram, QR-код салона в кабинете.
- [ ] **6. Профиль салона на странице записи.** Фото салона и мастеров (загрузка в кабинете), часы работы,
      адрес со ссылкой на карту, описание; выбор мастера с фото.
- [ ] **7. Типизированный клиент API.** `packages/api-client` из OpenAPI вместо ручных типов `apps/web/lib/types.ts`
      (отклонение от спецификации, см. docs/README.md).
- [ ] **8. Подготовка к запуску на сервере (без выкладки).** Dockerfile для API и веба, production
      docker-compose, проверка переменных, инструкция «как запустить на сервере в ЕС». Ничего не покупать.
- [ ] **9. Каталог и карта с фильтром по языку** (этап 3 плана): публичный поиск салонов, карта, фильтр PL/UA/RU/BY/EN.
- [ ] **10. Бонусы** (этап 4): правила «каждая N-я услуга со скидкой» по мастеру, услуге, интервалу; скидка на пустые часы.
